# 授業資料アシスタント（完成版）

このアプリを先に作り、各回のsolutionにコピーして未習の機能を削除しました。
exerciseはさらに学習箇所をコメントアウトしています。共有モジュールへの参照はなく、各フォルダで独立して動きます。

## 起動

毎回の授業開始時に、リポジトリのルートのターミナルでキーを非表示で入力し、同じターミナルから起動します。

```bash
source .venv/bin/activate
read -rsp "APIキー: " OPENAI_API_KEY; echo
export OPENAI_API_KEY
cd sample-app
python init_db.py
python main.py
```

常に実際のAPIを使います。
質問時は質問や参照資料を外部APIへ送信します。API利用料金が発生します。
生成モデルは **gpt-6-luna**。Responses API、reasoning.effort=none、最大出力600トークンを使います。
資料の検索（RAGのR）は形態素解析器 **Janome** を使い、手元のPCだけで行います。検索には外部APIを使いません。

Codespacesのポート8000番を開きます。ポートは非公開のまま使います。
終了時はサーバーをCtrl+Cで停止し、`unset OPENAI_API_KEY` を実行してターミナルを閉じます。
新しいターミナルではキーの再設定が必要です。キーは `.env`、Codespaces Secrets、シェルの設定ファイルに保存しません。
設定変更後はサーバーを再起動します。

## ファイルを読む順番

1. `one_shot.py` と `llm.py` の `ask_plain()`：最小のAPI呼び出し
2. `main.py` の `ask()`：チェックした機能の組み合わせで処理を選ぶ
3. `static/app.js` の `askQuestion()`：送信と表示
4. `knowledge.py`：資料の登録と、Janomeによるキーワード検索
5. `assignment_tools.py`：関数名と引数を検証し、DBを読む

Pydanticの入力モデルを除き、独自クラスや継承は使いません。
内包表記や複雑なコールバックを避け、for・if・辞書・普通の関数を中心にしています。

## 試す質問

画面の「回答に使う機能」で、キーワード検索と課題DBを選べます。初期状態はどちらも未選択です。

| キーワード検索 | 課題DB | 処理 | 質問の例 |
|---|---|---|---|
| なし | なし | 資料なしで回答（`ask_plain()`） | FastAPIとは？ |
| あり | なし | 検索した資料で回答（`ask_with_context()`） | SQLiteに保存するには？ |
| なし | あり | 課題DBの関数呼び出しで回答（`ask_assignments()`） | 未提出の課題は？ |
| あり | あり | 検索した資料を渡したうえで関数呼び出し | 第8回の提出物は何で、もう提出した？ |

Janomeが取り出す検索語の例：「SQLiteに保存するには？」→ sqlite, 保存。「第7回の提出物は？」→ 7, 提出。

## キーワード検索の仕組み

1. `extract_words()` が質問をJanomeで形態素に分け、名詞・動詞・形容詞の基本形を取り出す。
   助詞・助動詞・記号、「の」などの非自立語、「する」などのどこにでも出る語は除く。
2. 各資料も同じ方法で単語に分け、質問の単語がいくつ含まれるかを数える。
3. 一致数の多い順に上位件数だけをLLMへ渡す。取り出した検索語は画面の「学習用」欄で確認できる。

単語の表記が違うと一致しません（例: 「保管」と「保存」）。意味の近さは判定しないため、言い換えた質問では資料が見つからない場合があります。

## 資料の追加・更新・削除

`data/*.md` が原本です。`# 資料名` と `## 見出し` を付けて記述します。
1見出し1000文字以内、全体100断片以内。文脈は最大12000文字です。
サーバーを止めて `python init_db.py` で資料を再登録します。
登録は古い資料を置き換えます。検索は質問のたびに資料を単語に分けるため、索引の作成は不要です。
課題の既存の提出状況は再登録で上書きしません。教材の初期値へ戻すならDBを退避してから再作成します。

資料IDは再登録で変わる場合があります。評価にはファイル名・見出しも記録します。
教材の文章は参照元の学習内容を踏まえて新規作成した復習ノートで、原文の転載ではありません。
授業案内・課題の提出状況は架空です。

## 範囲と限界

- 1問ずつ回答する。会話履歴やログインは実装しない。
- 回答の引用IDの正しさは自動保証しない。実際の本文と照合する。
- プロンプトインジェクションの完全防御を保証しない。秘密や書き込み権限を渡さない。
- 回数制限は全利用者で共有し、1プロセス内で1分10回・起動後100回。再起動でリセット。
- これは予算上限ではない。CLIからの呼び出しにはこの制限は適用されない。
- 本番公開には認証、利用者別の資料権限、永続的な制限、利用量管理などが必要。
- APIの応答にキーや環境変数を含めない。
