# 完成版サンプル

LLMの呼び出し方の基本と、LLMを使うWebアプリ3つの完成版です。
4つのフォルダは互いのファイルを参照せず、それぞれ単独で動きます。

| フォルダ | アプリ | 学ぶこと | ポート |
|---|---|---|---|
| `llm-call/` | LLM呼び出しの基本（ターミナルで動く） | 1回だけ呼ぶ方法と、会話の履歴をのせて呼ぶ方法 | なし |
| `chat-app/` | チャットアプリ | 会話の履歴をブラウザに持ち、毎回まとめて送る | 8002 |
| `keyword-app/` | キーワード検索アプリ | RAG：Janomeで資料を探し、その資料をもとにLLMが答える | 8000 |
| `progress-app/` | 制作の進捗アプリ | Function Calling：LLMが関数を選び、PythonがSQLiteを読む | 8001 |

## 起動

毎回の授業開始時に、リポジトリのルートのターミナルでキーを非表示で入力し、同じターミナルから起動します。

```bash
export OPENAI_API_KEY=sk-********
cd sample-app/keyword-app   # ほかのアプリなら cd sample-app/chat-app など
python main.py
```

`llm-call/` はWebサーバーを使わず、ターミナルで `python one_shot.py` または `python chat.py` を実行します。

キーワード検索アプリはポート8000番、進捗アプリは8001番、チャットアプリは8002番をCodespacesの「ポート」タブから開きます。ポートは非公開のまま使います。
2つを同時に動かすときは、ターミナルを2つ使い、それぞれでキーを設定します。

- 常に実際のAPIを使います。質問するたびにAPI利用料金が発生します。
- 生成モデルは **gpt-6-luna**。Responses API、reasoning.effort=none、最大出力600トークンを使います。
- 終了時はサーバーをCtrl+Cで停止し、`unset OPENAI_API_KEY` を実行してターミナルを閉じます。
- キーは `.env`、Codespaces Secrets、シェルの設定ファイルに保存しません。

## LLM呼び出しの基本（llm-call）

```bash
cd sample-app/llm-call
python one_shot.py   # 1回だけ呼び出す
python chat.py       # 会話の履歴をのせて呼び出す（何も入力せずEnterで終わる）
```

### ファイルを読む順番

1. `one_shot.py` の `ask_once()`：質問の文字列だけを `input` に入れて送る
2. `chat.py` の `ask_with_history()` と `main()`：質問と回答を `history` のリストにため、毎回まとめて送る

2つの違いは `input` に入れるものだけです。指示文（各スクリプトの先頭にある `INSTRUCTIONS`）は同じです。

| | `one_shot.py` | `chat.py` |
|---|---|---|
| `input` に入れるもの | 今回の質問の文字列 | これまでの質問と回答のリスト |
| 前の会話 | 知らない | 知っている |
| 入力トークン数 | ほぼ一定 | 質問を重ねるたびに増える |

### 試すこと

1. `python one_shot.py` で「私の名前は佐藤です。」と送る。もう一度実行して「私の名前は？」と送る。→ 名前は分からない。
2. `python chat.py` で同じ2つを続けて送る。→ 前の会話を送っているので答えられる。
3. `chat.py` で質問を重ね、表示される入力トークン数が増えていくことを確かめる。

LLMそのものは前の会話を覚えていません。`store=False` でOpenAI側にも会話を保存しないため、覚えているように見えるのは、アプリが履歴を毎回送っているからです。
`chat.py` は履歴が長くなりすぎないよう、質問を最大10回（`MAX_TURNS`）までにしています。

## チャットアプリ（chat-app）

`llm-call/chat.py` をWebアプリにしたものです。

### ファイルを読む順番

1. `static/app.js`：`history` のリストに質問と回答をためる。送信のたびに `history` を全部サーバーへ送る
2. `main.py` の `chat()`：送られてきた履歴を確かめて、`ask_with_history()` を呼ぶ
3. `llm.py` の `ask_with_history()`：履歴のリストをそのまま `input` に入れてLLMへ送る

### 履歴をどこに持つか

履歴はブラウザの `history` 変数だけが持ち、サーバーは保存しません。そのため、次のようになります。

- 何人が同時に使っても、会話は混ざらない。
- ページを再読み込みすると、履歴は消える（「会話をリセット」と同じ）。
- 送られてくる履歴は書き換えられる可能性がある。サーバーは、役割が `user`・`assistant` のどちらかか、最後が質問か、長さと回数が上限内かを確かめる。

1つの会話の質問は最大10回です（`main.py` と `app.js` の `MAX_TURNS`。2か所を同じ値にします）。

### 試すこと

1. 「私の名前は佐藤です。」の次に「私の名前は？」と送る。→ 答えられる。
2. 「会話をリセット」を押して、もう一度「私の名前は？」と送る。→ 答えられない。
3. 質問を重ねて、画面下に表示される入力トークン数が増えていくことを確かめる。

## キーワード検索アプリ（keyword-app）

### ファイルを読む順番

1. `main.py` の `ask()`：質問を受け取り、①検索語を取り出す ②資料を探す ③LLMに答えさせる
2. `documents.py`：`data/*.md` を「## 見出し」ごとの資料に分ける
3. `search.py`：Janomeで単語を取り出し、一致した数で資料を並べる
4. `llm.py`：資料と質問をLLMに送る
5. `static/app.js` の `askQuestion()`：送信と表示

### 検索の仕組み

1. `extract_words()` が質問をJanomeで単語に分け、名詞・動詞・形容詞の基本形を取り出す。
   助詞・記号、「の」のような意味の薄い語、「する」のようにどこにでも出る語は除く。
2. `search_documents()` が各資料も同じ方法で単語に分け、質問の単語がいくつ含まれるかを数える。
3. 一致した数の多い順に、上位3件（`main.py` の `TOP_K`）をLLMへ渡す。1件も無ければAPIを呼ばない。

| 質問 | 取り出される検索語 |
|---|---|
| SQLiteに保存するには？ | sqlite, 保存 |
| ページを閉じてもデータが残るのはなぜ？ | ページ, 閉じる, データ, 残る |
| 第7回の提出物は？ | 7, 提出 |

単語の表記が違うと一致しません（例：「保管」と「保存」）。意味の近さは判定しないため、言い換えた質問では資料が見つからない場合があります。

### 資料の追加・更新・削除

`keyword-app/data/*.md` が原本です。`# 資料名` と `## 見出し` を付けて書き、1つの見出しの本文は1000文字以内にします。
資料は起動時に読み込むので、編集したらサーバーを再起動します。DBや索引の作成は不要です。
資料IDは起動時に順番に付けるため、資料を増減すると変わります。評価にはファイル名と見出しも記録します。

## 制作の進捗アプリ（progress-app）

### ファイルを読む順番

1. `main.py` の `ask()`：質問を受け取り、`ask_with_tools()` を呼ぶ
2. `llm.py` の `ask_with_tools()`：LLMに関数を選ばせ、結果を渡して回答させる（2回のAPI呼び出し）
3. `llm.py` の `run_tool()`：LLMが選んだ関数名と引数を確かめてから実行する
4. `progress_db.py`：SQLiteの `tasks` テーブルを作り、読み出す
5. `static/app.js` の `askQuestion()`：送信と、関数の結果の表示

### 進捗DB

`progress-app/progress.db` の `tasks` テーブルに、Webアプリ制作の「やること」と完了フラグを保存します。

| 列 | 内容 |
|---|---|
| id | 番号 |
| task | やること |
| done | 完了フラグ。SQLiteに真偽値の型が無いため1（True）/0（False）で保存し、APIでは `true` / `false` で返す |

LLMは `get_tasks` 関数を `status`（`all`・`todo`・`done`）付きで呼び出せます。実行するSQLは決まった3つの文だけです。
起動時に最初の6件を入れますが、すでにある行は上書きしません。初期値に戻すときは、サーバーを止めて `progress.db` を削除してから起動します。

| 質問の例 | LLMが選ぶはずの関数 |
|---|---|
| まだ終わっていない作業は？ | `get_tasks({"status":"todo"})` |
| 終わった作業を全部教えて | `get_tasks({"status":"done"})` |
| FastAPIとは？ | 関数を呼ばずに回答する場合がある |

## 書き方の方針

- Pydanticの入力モデルを除き、独自クラスや継承は使いません。
- 内包表記や複雑なコールバックを避け、for・if・辞書・普通の関数で書いています。
- 1つのファイルに1つの役割を持たせ、関数の先頭に何をするかを書いています。

## 範囲と限界

- 1問ずつ回答する。会話履歴やログインは実装しない。
- 回答の資料IDの正しさは自動では保証しない。実際の本文と照合する。
- プロンプトインジェクションの完全防御は保証しない。秘密や書き込み権限を渡さない。
- 利用回数の制限は実装しない。質問するたびにAPI利用料金が発生する。
- 本番公開には認証、利用者別の権限、利用量の管理などが必要。
- APIの応答にキーや環境変数を含めない。
- 授業案内・制作の進捗は架空のデータです。教材の文章は参照元の学習内容を踏まえて新規作成した復習ノートで、原文の転載ではありません。
