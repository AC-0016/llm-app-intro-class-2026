## RAGとは

Retrieval-Augmented Generation：検索拡張生成。

質問に関係する情報を検索し、その情報を入力に加えて生成します。
この教材では、登録した授業資料の中を検索します。

RAGはインターネット検索だけを指す言葉ではありません。
今回は単語の一致で探します。次回はベクトルで探します。
どちらも、検索して生成する構成は同じです。
<!-- 出典: https://arxiv.org/abs/2005.11401 -->

## 準備と質問時の処理

| 準備するとき（`init_db.py`） | 質問を受けたとき（`main.py`） |
|---|---|
| スライドを1枚ずつに分ける | 質問から検索語を取り出す |
| Janomeで単語に分ける | 単語が一致する資料を探す |
| 見出し・本文・単語をDBに保存する | 上位の資料をLLMへ渡す |
| | 回答と渡した資料を表示する |

準備は資料を直したときに1回、検索と生成は質問ごとに行います。
資料の形態素解析は準備のときに済ませ、質問のときは質問だけを解析します。

## 検索語を取り出す：extract_words()

```python
def extract_words(text):
    words = []
    for token in tokenizer.tokenize(text):
        parts = token.part_of_speech.split(',')
        if parts[0] not in USE_PARTS:
            continue
        if parts[1] in SKIP_DETAILS:
            continue
```

Janomeの `tokenize()` が、文章を単語（トークン）に分けます。
各トークンには品詞が付いています。品詞で使う語を選びます。

---

## 品詞で選ぶ

| 定数 | 値 | 意味 |
|---|---|---|
| `USE_PARTS` | 名詞、動詞、形容詞 | この品詞だけ使う |
| `SKIP_DETAILS` | 非自立、代名詞、接尾 | 名詞でも除く細分類 |
| `STOP_WORDS` | する、ある、いる、なる、できる、れる、られる | どの文章にも出る語 |

助詞（は・を・に）や記号（？）は `USE_PARTS` に無いので使いません。
「の」は非自立、「それ」は代名詞、「提出物」の「物」は接尾です。

---

## 基本形にそろえる

```python
        word = token.base_form
        if word == '*':
            word = token.surface
        word = word.lower()

        if word in STOP_WORDS:
            continue
        if word not in words:  # 同じ語は1回だけ入れる
            words.append(word)
    return words
```

「閉じて」の「閉じ」は、基本形「閉じる」になります。
辞書に無い語は基本形が `'*'` なので、書かれた形（`surface`）を使います。
`lower()` で `SQLite` と `sqlite` を同じ語にします。

## forとifで数える

```python
    results = []
    for document in documents:
        score = 0
        for keyword in keywords:
            if keyword in document['words']:
                score += 1

        if score > 0:
            results.append({
                'id': document['id'],
                ...
                'score': score,
            })
```

`keywords` は質問の検索語、`document['words']` は資料の単語リストです。
`in` は、リストにその語があるかを調べます。

## ループ中のscore

12枚目「学習と推論」を処理する例です。

| タイミング | keyword | `words` に含まれる | score |
|---|---|---|---|
| 開始 | まだ取り出していない | 未判定 | 0 |
| 1回目 | 学習 | 含まれる | 1 |
| 2回目 | 推論 | 含まれる | 2 |
| 3回目 | 違い | 含まれない | 2 |

次の資料を処理するときは、`score = 0` から始めます。
前の資料の点数を引き継ぐと、順位が変わってしまいます。

---

## 上位件数：top_k

```python
    results.sort(key=get_score, reverse=True)
    return results[:top_k]


def get_score(result):
    return result['score']
```

`get_score()` は辞書から点数を取り出す関数です。`sort()` に渡します。
`reverse=True` で大きい順に並べます。
`[:top_k]` は先頭から `top_k` 件まで取り出す書き方です。
`top_k` には `main.py` の `TOP_K = 3` が渡されます。

---

## 並べ替えと上位選択の結果

「学習と推論の違いは？」で一致する資料は6件です。
12枚目が2点、2・7・8・9・35枚目が1点です。

| `TOP_K` | LLMに渡す資料 | 理由 |
|---|---|---|
| 1 | 12 | 先頭の1件 |
| 3 | 12、2、7 | 2点が1件、1点はID順に2件 |
| 5 | 12、2、7、8、9 | 1点はID順に4件 |

「TransformerのAttentionとは？」は9枚目（2点）と8枚目（1点）の2件だけです。
`TOP_K` が3でも2件しか渡りません。最大件数であって、必ず返る数ではありません。

---

## 同点の資料の扱い

`sort()` は、同じ点数なら元の順番を保ちます。
元の一覧は `load_documents()` がID順に読んだものです。
同点ならIDの小さい資料が先になります。

1点の資料が5件あっても、`TOP_K = 3` なら2件しか渡りません。
先に並んだことだけでは、答えに必要な資料とは判断できません。
画面の「一致した検索語の数」と本文を見て確かめます。

    found = search_documents(keywords, documents, TOP_K)

## 発展：STOP_WORDS を増やす

「この授業で使うモデルは何？」の検索語は「授業、使う、モデル」です。
「使う」は多くの資料に出るので、除く例です。

1. `search.py` の `STOP_WORDS` に `'使う'` を足す
2. `python init_db.py` を実行し、資料側の単語も作り直す
3. `python main.py` で再起動し、検索語が「授業、モデル」になることを見る

資料側の単語も同じ `extract_words()` で作っているので、
`search.py` を変えたら `init_db.py` をやり直します。

## 検索と生成の失敗を分ける

| 検索結果 | 回答 | 最初に調べる場所 |
|---|---|---|
| 必要な根拠がない | 誤答 | 検索語、`STOP_WORDS`、`TOP_K` |
| 必要な根拠がある | 誤答 | 指示文、渡した本文、モデルの出力 |
| 根拠がない | 回答を控える | 言い換えで見つかるか |
| 根拠がある | 正答 | 別の質問でも確かめる |

検索結果を見ずに、指示文だけを変え続けないようにします。
画面の「検索語」と「LLMに渡した資料」が、切り分けの材料です。

---

## 失敗した場所の切り分け

| 観察した状態 | まず確認すること |
|---|---|
| `janome` のimportで止まる | 仮想環境と依存パッケージ |
| 「documents.db がありません」 | `python init_db.py` を実行したか |

| 渡した資料が3件を超える、点数順でない | 実習3の2行と仮の `return` |
| 「質問から検索語を取り出せませんでした」 | 名詞を含む質問にする |
| 「API呼び出しに失敗しました」 | キー・モデル・利用枠 |
| 資料を直しても変わらない | `init_db.py` の再実行と再起動 |
