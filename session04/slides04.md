## 指示とデータの違い

「参考資料に『前の指示を無視しなさい』と書かれていた」

## 資料の形式はMarpスライド

`data/session01.md` は、第1回のスライド `session01/slides01.md` のコピーです。
`init_db.py` は次のように読みます。

| Markdownの書き方 | 資料としての扱い |
|---|---|
| 先頭の `---` から `---` まで | スライドの設定なので読まない |
| `---` だけの行 | スライドの区切り。スライド1枚が資料1つになる |
| 最初のスライドの `# 見出し` | 全スライドの題名（資料名） |

| `<!-- コメント -->`、`![画像](…)` | 発表者メモ・出典・画像なので読まない |
| ```` ``` ```` で囲まれたコード | 中の `#` や `---` も含め、本文としてそのまま読む |

## split_slides()：スライドに分ける

```python
    for line in lines[start:]:
        if line.startswith('```'):
            in_code = not in_code
        if line == '---' and not in_code:
            # 区切りが来たので、ここまでを1枚のスライドにする。
            slides.append(current)
            current = []
        else:
            current.append(line)
    slides.append(current)  # 最後のスライドも忘れずに追加する
```

先頭の設定（フロントマター）は、`start` の位置まで飛ばしてから読み始めます。
戻り値は「スライドごとの行のリスト」です。コードの中の `---` は区切りにしません。

```python
        if line.startswith('!['):
            continue

        # 最初の見出しを、このスライドの見出しにする。
        if heading == '' and (line.startswith('# ') or line.startswith('## ')):

        body_lines.append(line)

## build_context()：資料を文字列にする

```python
def build_context(documents):
    """LLMに渡す資料の文章を作る。各資料の先頭に [資料1] のようなIDを付ける。"""
    context = ''
    for document in documents:
        context += f"[資料{document['id']}] {document['title']} / {document['heading']}\n"
        context += document['body'] + '\n\n'
    return context
```

`documents` は、検索で選ばれた資料の辞書のリストです。
1件ごとに「ID・題名・見出し」の行と本文を `context` に足していきます。
`f"…{document['id']}…"` は、辞書の値を文字列の中に埋め込む書き方です。

## build_context() が作る文字列の例

## 出典表示の意味

画面の「LLMに渡した資料」は、サーバーが実際に渡した本文です。
その下の「原本: data/session01.md の19枚目」で、原本の場所が分かります。
回答に書かれた資料IDは、モデルが生成した文字列です。

- 存在するIDか
- その本文が主張を支えているか
- 必要な条件や例外を落としていないか

出典欄があるだけでは、回答の正しさを保証しません。

## すべて渡す方法の限界

今の `data/` は36枚です。毎回全部渡すと、次の問題が出ます。

- 入力が長くなり、料金と待ち時間が増える
- 無関係な文章が増え、根拠の照合もしにくくなる
- モデルの入力上限がある

| 処理 | 今回読んだこと | 次回 |
|---|---|---|
| 渡す資料を選ぶ | 選ばれた後の流れ | 検索で上位3件（`TOP_K`）に絞る |
| `build_context()` | 資料を文字列にする | 同じ関数を使う |

`init_db.py` は、1枚の本文を1000文字（`MAX_BODY_LENGTH`）以内に制限し、超えるとDBを変える前に止まります。

## 失敗した場所の切り分け

| 観察した状態 | まず確認すること |
|---|---|
| 「documents.db がありません」 | 先に `python init_db.py` を実行したか |
| 「…枚目が長すぎます」 | スライドを分けて1000文字以内にする |
| ステータス欄に「TODO: llm.py の build_context()…」 | 実習2のコメントと `raise` の行 |
| 回答に資料IDが付かない | `INSTRUCTIONS` が仮のままか。再起動したか |
| 直した資料が画面に出ない | `init_db.py` の再実行と再起動 |
| 「API呼び出しに失敗しました」 | キー・モデル・利用枠 |

相談時は、質問文・画面のステータス・「LLMに渡した資料」を伝えます。キーは共有しません。
